Brief techno du hackathon

Ce qu'il faut savoir pour démarrer : règles, connexion à votre compte Azure OpenAI, librairies utiles, OCR, architecture type et bonnes pratiques pour tenir le quota.

Brief techno pour les équipes

Le hackathon se déroule sur une souscription Azure dédiée. Chaque équipe dispose de son propre compte Azure AI Foundry, dont elle appelle les modèles par l'API Azure OpenAI. Pour le reste, le choix des outils est libre : ce qui suit est une base pour démarrer vite, pas une liste imposée.

Les quatre règlesBackend en Python. Seul LLM autorisé : le compte Azure OpenAI de l'équipe. Clé dans un fichier .env, jamais dans Git. Quota annoncé à respecter.
LibreFrameworks et librairies Python, interface, architecture. L'interface peut être en Python (Streamlit, Chainlit) ou un front web séparé.
FourniUn point de terminaison Azure OpenAI, une clé et trois modèles : gpt-6.1-terra et gpt-6.1-sol pour le chat (tous deux acceptent aussi les images), et text-embedding-3-small pour les embeddings. S'y ajoutent un partage de fichiers Azure Files par équipe et le partage commun common.

Connexion à Azure OpenAI

Azure OpenAI accepte le SDK OpenAI standard. Il suffit de pointer vers le point de terminaison de l'équipe. Le paramètre model prend le nom du déploiement, qui est ici le nom du modèle : gpt-6.1-terra, gpt-6.1-sol ou text-embedding-3-small.

AZURE_OPENAI_ENDPOINT est l'adresse de base de votre équipe, sans /openai/v1 : le code ajoute ce suffixe lui-même, et l'enlève s'il a été collé par erreur. Reprenez exactement l'adresse remise par l'organisation.

Remplit le numéro d'équipe dans les fichiers .env ci-dessous.

Fichier .env

AZURE_OPENAI_ENDPOINT=https://aoai-hackathon-digital-teamXX.openai.azure.com
AZURE_OPENAI_API_KEY=<clé remise par l'orga>
AZURE_OPENAI_MODEL=gpt-6.1-terra

Python · pip install openai python-dotenv

import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
endpoint = os.environ["AZURE_OPENAI_ENDPOINT"].rstrip("/").removesuffix("/openai/v1")
client = OpenAI(
    base_url=f"{endpoint}/openai/v1/",
    api_key=os.environ["AZURE_OPENAI_API_KEY"],
)

resp = client.chat.completions.create(
    model=os.environ["AZURE_OPENAI_MODEL"],
    messages=[{"role": "user", "content": "Résume ce sinistre en 3 lignes : ..."}],
    max_completion_tokens=500,
)
print(resp.choices[0].message.content)
print(resp.usage)  # tokens consommés par l'appel

Les frameworks (LangChain, LlamaIndex, Semantic Kernel…) ont tous un connecteur Azure OpenAI : ils prennent les mêmes trois valeurs.

Accéder aux fichiers (Azure Files)

Chaque équipe dispose d'un partage Azure Files à son nom (lecture, écriture, suppression) et du partage common en lecture seule. Chaque partage a son jeton SAS, valable jusqu'au 23 novembre 8h UTC. Ajoutez dans le .env, sans le « ? » initial du SAS :

Fichier .env (suite)

AZURE_FILES_ACCOUNT_URL=https://sthackathondigital.file.core.windows.net
AZURE_FILES_TEAM_SHARE=teamXX
AZURE_FILES_TEAM_SAS=<SAS du partage de l'équipe>
AZURE_FILES_COMMON_SHARE=common
AZURE_FILES_COMMON_SAS=<SAS du partage common>

Python · pip install azure-storage-file-share

import os
from dotenv import load_dotenv
from azure.storage.fileshare import ShareClient

load_dotenv()
common = ShareClient(os.environ["AZURE_FILES_ACCOUNT_URL"],
                     share_name=os.environ["AZURE_FILES_COMMON_SHARE"],
                     credential=os.environ["AZURE_FILES_COMMON_SAS"])
for item in common.list_directories_and_files():
    print(item["name"])
data = common.get_file_client("exemple.pdf").download_file().readall()

Réseau et accès

Azure OpenAI et Azure Files ne répondent que depuis les réseaux autorisés. Ailleurs, vous obtiendrez une erreur 403 (Access denied due to Virtual Network/Firewall rules pour le modèle, AuthorizationFailure pour les fichiers) : vos clés ne sont pas en cause. Avant le jour J, vous pouvez tout installer et tester l'OCR hors de ces réseaux ; seuls les appels au modèle et aux fichiers attendront.

Git en SSH : si git push reste bloqué, le port 22 est filtré. Ajoutez ceci dans ~/.ssh/config pour passer par le port 443, ou clonez en HTTPS :

~/.ssh/config

Host gitlab.com
  HostName altssh.gitlab.com
  Port 443
  User git

Lire des documents et faire de l'OCR

Aucun service d'OCR n'est fourni sur Azure : les documents se lisent sur votre poste, par leur texte natif ou un OCR local, ou par la vision du modèle. Commencez par le moins cher et ne montez d'un cran que si le résultat ne suffit pas.

1 · Gratuit

Texte natif du PDF

Beaucoup de PDF contiennent déjà leur texte. PyMuPDF, pdfplumber ou pypdf le lisent instantanément, sans OCR.

2 · Gratuit

OCR local

Pour les scans propres. RapidOCR, Tesseract ou Docling, sur le poste. Les documents ne quittent pas la machine.

3 · Quota de l'équipe

Vision du modèle

Pour les photos, les documents difficiles ou quelques pages : envoyer l'image à gpt-6.1-terra ou gpt-6.1-sol, qui acceptent tous deux les images.

OutilInstallationPoints fortsLimites
PyMuPDF, pdfplumber, pypdfpipTexte natif du PDF, instantané. pdfplumber lit aussi les tableaux simples.Rien sur un scan ou une photo.
RapidOCRpipOCR rapide sur CPU, bonne qualité, aucun programme à installer.Peu de mise en page.
Tesseractpip + programme (brew, apt, winget) avec le pack de langue françaisLe classique, léger, bon en français sur des documents propres.Faible sur les tableaux et les photos de travers. Demande des droits d'installation.
EasyOCR, PaddleOCR, docTRpip, modèles à téléchargerPlus robustes sur les photos et les scans moyens.Lourds, lents sans GPU.
Doclingpip, modèles à téléchargerRestitue titres et tableaux en Markdown, prêt pour un RAG. OCR intégré si besoin.Plus lent sur de gros volumes.
À préparer avant le jour J. La plupart de ces outils téléchargent leurs modèles au premier lancement, ce que le proxy peut bloquer. Installez-les et lancez-les une première fois avant l'événement. Aucun OCR local ne lit bien l'écriture manuscrite : passez alors par la vision du modèle.

Exemple · pip install pymupdf rapidocr-onnxruntime

import fitz  # PyMuPDF
from rapidocr_onnxruntime import RapidOCR

ocr = RapidOCR()
doc = fitz.open("sinistre.pdf")
pages = []
for page in doc:
    text = page.get_text()
    if len(text.strip()) < 20:  # page scannée : pas de texte natif
        img = page.get_pixmap(dpi=200).tobytes("png")
        result, _ = ocr(img)
        text = "\n".join(line[1] for line in (result or []))
    pages.append(text)
print("\n\n".join(pages))

Architecture type

Une architecture simple, à adapter. Pour aller vite, l'interface, l'API et l'orchestration peuvent vivre dans un seul script Streamlit ou un notebook.

Interface
Streamlit, Chainlit, web. Saisie, upload, affichage.
→
API optionnelle
FastAPI. Valide les entrées, porte la logique métier.
→
Orchestration LLM
Prompts versionnés, sorties structurées, appel d'outils, agents.
→
Azure OpenAI
Compte de l'équipe : gpt-6.1-terra, gpt-6.1-sol, text-embedding-3-small.
Outils et données au besoin
RAG : découpage, embeddings, base vectorielle locale. Fichiers : partage Azure Files de l'équipe et partage common. Outils : fonctions Python, API métier simulées, fichiers de données fictives.

Pour tenir le quota

RéflexeEffet
Choisir le bon modèleComparer les tarifs de gpt-6.1-terra et gpt-6.1-sol, et garder le moins cher pour le simple : classification, extraction courte, routage.
Borner les réponsesmax_completion_tokens sur chaque appel, des prompts qui demandent une réponse courte.
Garder un début de prompt stableLes consignes fixes en tête du prompt profitent du cache, facturé moins cher.
Calculer les embeddings une foisLes stocker dans la base vectorielle, ne pas les recalculer à chaque lancement.
Surveiller usageChaque réponse indique ses tokens. Les journaliser aide à repérer une boucle ou un prompt trop long.
